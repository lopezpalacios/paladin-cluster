2-of-2 notary signing, full picture

What happens on every sign request

  1. Paladin node A needs the notary key for a transaction (approve a noto transfer, sign a public tx). It calls its wallet, which is wired to the signing module plugin instead of a plain key store.
  2. The module builds the attestation: sha256("paladin-2of2-v1:" ‖ payloadHex ‖ ":" ‖ keyIdentifier). This binds the approval to one exact payload. A signature for this request is useless for any other.
  3. The module sends POST /cosign over the Tailscale tunnel to Device B's agent: key identifier, algorithm, payload hex, attestation hash. No private key material ever leaves Device A.
  4. Agent B runs the policy allowlist (regex over key identifiers). If allowed, it signs the attestation with its own P-256 key and returns {approved: true, signature}. If not, it returns a rejection with a reason. Every decision lands in the audit log.
  5. The module verifies the agent's signature against the public key configured at setup. A forged or stale response fails here.
  6. Only now does the module sign with its local key and hand the signature back to the node.
  7. Device B runs the identical setup mirrored: its module calls Agent A. Steps 2–6 repeat.

Security properties

PropertyHow it holds
Neither device signs aloneLocal sign step happens only after a live, verified approval from the other device. Kill the agent and the key is frozen.
No key material crosses the wireOnly payload hex + attestation hash leave the device. Keys never do.
Approvals can't be replayedThe attestation binds payload + key identifier. A captured signature verifies for nothing else.
Wrong identity can't be approvedServer-side allowlist per key identifier; rejection is audited.
Stale agent response rejectedModule verifies the ECDSA signature over the attestation with the pinned public key.

What it is not. Cryptographic key splitting. The notary's full private key still lives on the module's device. This is operational 2-of-2. Signing requires both parties live at the same time. True 2P-ECDSA key splitting is the roadmap item that removes that trust.

Configuration

Module config (inside each Paladin node's signingModules section of the CR):

signingModules:
  - name: notary-2of2
    plugin: { type: c-shared, library: /app/signingmodules/libnotary2of2.so }
    configJSON: |
      {
        "signer": {
          "keyStore": { "type": "static", "static": { "keys": {
            "seed": { "encoding": "none", "inline": "<mnemonic>" } } } },
          "keyDerivation": { "type": "bip32" }
        },
        "cosigner": {
          "url": "http://<other-device>:9191",
          "publicKey": "<agent public key hex>",
          "timeoutSeconds": 10
        }
      }

wallets:
  - name: notary-2of2-wallet
    keySelector: ".*"
    signerType: plugin
    signerPluginName: notary-2of2

Agent config (per device):

{
  "listen": ":9191",
  "privateKey": "<hex DER EC private key>",
  "allowedKeyIdentifiers": ["notary@node.*"]
}
